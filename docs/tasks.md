# تاسكات تطبيق إدارة المبيعات بالتقسيط (نسخة محدّثة نهائية)

تطبيق Flutter، أندرويد فقط (تابلت)، أوفلاين بالكامل، مستخدم واحد
(صاحب المحل)، بشكل SPA بثلاث صفحات رئيسية (منتجات، زبائن، حسابات)
عبر شريط تنقل سفلي — بدون أي مرحلة اعتماد/موافقة، وكل حذف هو حذف
مؤقت (Soft Delete) قابل للاسترجاع.

كل تاسك تحته نسخ ولصق مباشر لـ AI coding agent. لا تنتقل للتاسك
الجاي إلا بعد ما التالي يشتغل وتتأكد منه بنفسك.

---

## المرحلة صفر: الأساس

### تاسك 0.1 — إعداد المشروع والتنقل
```
أنشئ مشروع Flutter جديد (أندرويد فقط). أضف هذه الحزم بملف pubspec:
drift, sqlite3_flutter_libs, path_provider, path, drift_dev (dev),
build_runner (dev), file_picker, share_plus. لا تضيف أي حزمة أخرى
بهذه المرحلة. أنشئ Scaffold رئيسي بشريط تنقل سفلي (BottomNavigationBar)
بثلاثة تبويبات: المنتجات، الزبائن، الحسابات — كل تبويب يفتح شاشة
فاضية بعنوانه فقط حالياً. استخدم IndexedStack حتى ما تنعاد بناء
الشاشات عند التنقل. تأكد المشروع يبني والتنقل بين التبويبات يشتغل.
```

### تاسك 0.2 — جداول Drift
```
أنشئ ملف database.dart بمجلد lib/services. عرّف جداول Drift التالية
بدون أي منطق إضافي، فقط تعريف الحقول والأنواع والعلاقات:

- Products: id, name, price, isDeleted, createdAt, updatedAt
- Customers: id, name, address, phone, isDeleted, createdAt
- Sales: id, customerId, productId, originalPrice, interestAmount
  (مبلغ ثابت، ليس نسبة), totalAmount, months, monthlyWithInterest,
  monthlyWithoutInterest, startDate, isDeleted, createdAt
- Installments: id, saleId, monthNumber, dueDate, baseAmount,
  actualDue, totalPaid, isPaid
- Payments: id, installmentId, amount, paymentDate, note (nullable)

لا يوجد جدول أو حقل لأي حالة اعتماد/انتظار — كل عملية بيع فعالة
فور إنشائها. لا تكتب أي DAO أو Query الآن، فقط الجداول والعلاقات.
شغّل build_runner وتأكد الملفات المولّدة تطلع بدون أخطاء.
```

### تاسك 0.3 — اختبار اتصال قاعدة البيانات
```
أضف زر تجريبي بأي شاشة يضيف منتج وهمي بقاعدة البيانات ويطبعه
بالـ console للتأكد إن Drift شغّال صح. بعد التأكد احذف الزر.
```

## المرحلة 1: المنتجات (الصفحة الأولى)

### تاسك 1.1 — DAO المنتجات
```
أنشئ ProductDao بميثودات: إضافة منتج، تعديل منتج، حذف مؤقت (تحديث
isDeleted فقط)، استرجاع منتج محذوف، جلب كل المنتجات الغير محذوفة
(كـ Stream)، جلب المنتجات المحذوفة، بحث بالاسم.
```

### تاسك 1.2 — واجهة قائمة المنتجات
```
ابنِ شاشة المنتجات (lib/screens/products) تعرض رقم المنتج والاسم
والسعر بقائمة. أضف شريط بحث بالأعلى يفلتر بالاسم مباشرة أثناء
الكتابة، وخيار ترتيب/تصفية (فرز حسب الاسم أو السعر تصاعدي/تنازلي).
استخدم StreamBuilder مرتبط بـ ProductDao. تصميم Material 3 minimal
مناسب لشاشة تابلت.
```

### تاسك 1.3 — إضافة وتعديل منتج
```
أضف نموذج (نافذة منبثقة أو صفحة) لإضافة منتج أو تعديله: حقول الاسم
والسعر فقط (رقم المنتج تلقائي)، مع تحقق بسيط (الاسم غير فاضي،
السعر رقم موجب). اربطه بـ ProductDao.
```

### تاسك 1.4 — حذف واسترجاع منتج
```
أضف خيار حذف مؤقت للمنتج من القائمة (سحب أو زر)، وشاشة منفصلة
بسيطة تعرض المنتجات المحذوفة مع خيار استرجاع لكل منتج.
```

## المرحلة 2: الزبائن (الصفحة الثانية)

### تاسك 2.1 — DAO الزبائن
```
أنشئ CustomerDao بنفس نمط ProductDao: إضافة، تعديل، حذف مؤقت،
استرجاع، جلب الكل (Stream)، بحث بالاسم.
```

### تاسك 2.2 — استعلامات إجمالي المطلوب وحالة الشهر الحالي
```
أضف بملف منفصل (customer_summary_dao.dart أو داخل CustomerDao)
استعلامات لكل زبون: مجموع كل الأقساط غير المدفوعة عبر كل عملياته
(المبلغ الكلي المطلوب منه)، وقسط الشهر الحالي (installment اللي
dueDate يقع بالشهر الحالي) مع حالته (isPaid أو لا). هذي بيانات
مُشتقة (computed) مو حقول مباشرة بجدول Customers.
```

### تاسك 2.3 — واجهة قائمة الزبائن
```
ابنِ شاشة الزبائن تعرض لكل زبون: الاسم، الهاتف، المبلغ الكلي
المطلوب منه (من تاسك 2.2)، قسط الشهر الحالي، وحالة الدفع (مدفوع/
غير مدفوع) بلون واضح (أخضر/أحمر). أضف شريط بحث بالاسم، وفلتر يعرض
فقط: الكل / الدافعين هذا الشهر / غير الدافعين. زر إضافة زبون جديد
بنموذج (اسم، عنوان، هاتف).
```

### تاسك 2.4 — تأشير سريع لدفع القسط من القائمة
```
بقائمة الزبائن، أضف زر/سويتش سريع بجانب كل زبون غير دافع هذا الشهر
يسجل دفعة كاملة لقسط الشهر الحالي مباشرة بدون فتح صفحة التفاصيل
(يستدعي PaymentDao اللي راح ننشئه بالمرحلة 4). لو ما اكتملنا
PaymentDao بعد، اربطه لاحقاً — بس جهّز الـ UI الآن.
```

### تاسك 2.5 — صفحة تفاصيل الزبون (هيكل)
```
أنشئ صفحة تفاصيل الزبون تفتح عند الضغط على زبون من القائمة. تعرض
معلوماته الأساسية (الاسم، العنوان، الهاتف) بالأعلى، وتحتها قائمة
فاضية بعنوان "المنتجات المأخوذة" — بيانات حقيقية تُضاف بالمرحلة 3.
```

## المرحلة 3: منطق البيع والفائدة

### تاسك 3.1 — خدمة حساب الأقساط (فائدة مبلغ ثابت)
```
أنشئ installment_calculator.dart بدالة صافية (pure function) تاخذ:
السعر الأصلي، مبلغ الفائدة الثابت، وعدد الأشهر. ترجع: المبلغ الكلي
(السعر + الفائدة)، القسط الشهري مع الفائدة (المبلغ الكلي ÷ الأشهر)،
القسط الشهري بدون فائدة (السعر الأصلي ÷ الأشهر). لا فائدة نسبية،
مبلغ ثابت فقط. لا تربطها بقاعدة بيانات، فقط دالة رياضية.
```

### تاسك 3.2 — اختبار وحدة لحساب الأقساط
```
اكتب unit test لدالة installment_calculator يغطي: فائدة مبلغ ثابت
عادي، فائدة صفر، وحالة شهر واحد فقط. تأكد كل النتائج صحيحة رياضياً.
```

### تاسك 3.3 — DAO عمليات البيع
```
أنشئ SaleDao: دالة إنشاء عملية بيع جديدة تستخدم installment_calculator
وتولّد فوراً سجل Installment لكل شهر (بدون أي حالة انتظار) بتاريخ
استحقاق = تاريخ البداية + رقم الشهر، والمبلغ الأساسي = القسط الشهري
مع الفائدة. دالة تعديل عملية بيع (فقط تحدّث الأقساط الغير مدفوعة،
ما تلمس أقساط فيها دفعات مسجلة). دالة حذف مؤقت. دالة استرجاع. دالة
جلب كل عمليات بيع زبون معين (غير المحذوفة).
```

### تاسك 3.4 — واجهة إضافة منتج لزبون
```
بصفحة تفاصيل الزبون، أضف زر "إضافة منتج" يفتح نموذج: اختيار منتج
من قائمة المنتجات الموجودة (السعر يُعبّى تلقائياً من سعر المنتج)،
حقل مبلغ الفائدة الثابت، حقل عدد الأشهر. اعرض المبلغ الكلي والقسط
الشهري كمعاينة قبل الحفظ. عند الحفظ يستدعي SaleDao وينشئ العملية
والأقساط فوراً.
```

### تاسك 3.5 — عرض المنتجات المأخوذة بصفحة الزبون
```
بصفحة تفاصيل الزبون، اعرض لكل عملية بيع (منتج مأخوذ): اسم المنتج،
السعر الأصلي، مبلغ الفائدة، المبلغ الكلي، عدد الأشهر، المبلغ
المتبقي (مجموع الأقساط الغير مدفوعة). كل عملية بيع تظهر ككرت
منفصل قابل التوسيع لعرض جدول أقساطها.
```

## المرحلة 4: الدفعات والترحيل

### تاسك 4.1 — DAO الدفعات
```
أنشئ PaymentDao: دالة تسجيل دفعة جديدة على قسط معين، تحدّث totalPaid
بالقسط، وتحدّث isPaid إذا وصل المبلغ الفعلي المطلوب (actualDue).
اربط بيها زر الدفع السريع من تاسك 2.4.
```

### تاسك 4.2 — عرض المتبقي من القسط (بدون ترحيل)
```
لا يوجد أي ترحيل بين الأشهر. كل قسط مستقل تماماً بذاته. بعد كل دفعة
بـ PaymentDao، حدّث totalPaid فقط (بالجمع مع الدفعة الجديدة). إذا
totalPaid >= actualDue اجعل isPaid = true. إذا totalPaid أقل من
actualDue يبقى isPaid = false ويُحسب "المتبقي من هذا القسط" = actualDue
- totalPaid ويُعرض بواجهة الزبون. لا تلمس أي قسط آخر ولا تنشئ أي حقل
جديد لرصيد زائد أو ناقص — الدفعة تخص القسط المحدد فقط وخلاص.
```

### تاسك 4.3 — اختبار وحدة للدفعات الجزئية
```
اكتب unit test يغطي: دفع أقل من actualDue (يبقى isPaid = false
والمتبقي = الفرق)، دفع مضبوط بالضبط (isPaid = true)، دفع أكثر من
actualDue (isPaid = true بدون أي تأثير على أقساط أخرى)، ودفعتين
بنفس القسط تتجمعان صح بـ totalPaid.
```

### تاسك 4.4 — واجهة تسجيل دفعة تفصيلية
```
بجدول أقساط كل عملية بصفحة تفاصيل الزبون، أضف زر تسجيل دفعة لكل
قسط غير مدفوع بالكامل: مبلغ، تاريخ، ملاحظة اختيارية. اربطه بـ
PaymentDao.
```

### تاسك 4.5 — تلوين الأقساط المتأخرة
```
بجدول الأقساط، أضف تحقق: إذا dueDate أقل من تاريخ اليوم وisPaid لا
يزال false، اعرض الصف بلون أحمر مع عدد أيام التأخير.
```

## المرحلة 6: النسخ الاحتياطي

### تاسك 6.1 — تصدير/استيراد يدوي
```
أضف شاشة إعدادات بسيطة بزر "تصدير نسخة احتياطية" يصدّر قاعدة
البيانات كملف واحد (استخدم file_picker لاختيار مكان الحفظ)، وزر
"استيراد نسخة احتياطية" يقرأ نفس نوع الملف ويستعيد البيانات
(استبدال كامل مع تأكيد قبل التنفيذ لأنه يمسح البيانات الحالية).
```

### تاسك 6.2 — نسخ احتياطي تلقائي دوري
```
أضف خدمة تصدّر تلقائياً نسخة احتياطية كل ما يُفتح التطبيق (أو مرة
كل 24 ساعة كحد أقصى) إلى مجلد عام على الجهاز (مثل Downloads أو
مجلد مخصص Documents/AppBackups يبقى بعد حذف التطبيق). احتفظ بآخر
7 نسخ فقط بأسماء فيها التاريخ والوقت، واحذف الأقدم تلقائياً. لا
حاجة لأي ربط حساب Google أو صلاحيات OAuth — فقط كتابة ملف بمجلد
عام. اطلب صلاحية الوصول للتخزين لو احتاجها أندرويد.
```
